解释器应指向 `/home/lizishuo/miniconda3/envs/nanochat/bin/python`。若环境不存在或第三方依赖缺失，先解决环境，不把 `--help` 成功当作模型实验通过。后面写入的 `experiments/` 文件是你实际执行教程时产生的正式成果；本指导不预先生成成绩。大数据、tokenizer、权重放在 `NANOCHAT_BASE_DIR`，不要加进 Git。

使用 [隔离合成数据脚本](scripts/prepare_toy.py)。这个脚本不下载文件，不修改生产代码，不覆盖任何已存在的目标目录。以下路径仅供学习实验；若已存在，换一个新后缀，不能删除旧数据再重跑。

```bash

```

脚本创建 1,200 条 train 和 1,200 条 val 合成句子、两份含 `text` 列的 parquet、本项目 RustBPETokenizer 训练产生的词表，以及准确的 token_bytes。`synthetic_provenance.json` 记录来源。train 与 val 使用不同模板，但这种重复数据只用于功能 smoke，不能拿 val loss 评价真实语言能力。临时根目录重启后可能丢失；要长期保存可换到自己有权限的大数据盘路径，并在报告中记录。

## 第二步：逐项验证 round-trip

<abbr title="Round-trip · 往返验证。本文检查完整字符串经 encode 转为 token IDs 再 decode 后逐字符相等；不要求每个单独 token 都能解码为合法 UTF-8 字符。">round-trip</abbr> 的断言运行在 [真实 tokenizer 检查脚本](scripts/roundtrip.py)：

```bash
python .agents/docs/career_roadmap/w2/scripts/roundtrip.py --output experiments/inference_infra/reports/token_roundtrip.json
```

打开 JSON，确认 `status=ok` 且有六条 `cases`：英文、中英混合、换行与空白、数字、emoji 与重音字符、空字符串。逐条看 `text` 和 `token_ids`：token 数不等于汉字数，也不等于 UTF-8 字节数。空字符串普通 encode 应为空；加 BOS 后才有开头标记。脚本另外验证 batch encode 与逐条 encode 一致、九个特殊 token ID 不冲突、token_bytes 的长度等于实际词表大小且特殊 token 字节数为零。

<abbr title="BOS / Beginning of Sequence · 序列起点标记。本文文档编码时由 prepend 显式添加；它的 ID 是 tokenizer 定义的特殊 ID，不应假定固定为某个整数。">BOS</abbr> 需要与普通文本区别处理：`decode(encode(text, prepend=bos))` 会包括特殊标记，因此脚本比较 `bos_ids[1:]`，不把标记当原文。

## 第三步：验证真实 dataloader 一个批次

```bash
python .agents/docs/career_roadmap/w2/scripts/roundtrip.py --check-data --output experiments/inference_infra/reports/token_data_roundtrip.json
rg -n 'row_capacity|best_idx|cpu_inputs.copy_|cpu_targets.copy_' nanochat/dataloader.py
```

该脚本用每个 split 的真实 loader 取一批 `[1,32]`；训练时 loader 默认 buffer_size 为 1000，教学检查用 4 降低等待。它读取 parquet 第一 row group，检查 `text` 列非空且元素为字符串，然后检查：

1. `x/y` 形状 `[B,T]=[1,32]`、整数类型；
2. `x[:,1:] == y[:,:-1]`，说明 labels 向右错位一个 token；
3. 每行输入以 BOS 起头，ID 都在词表范围；
4. train 与 val 都能产出，不会卡在空 train split。

<abbr title="Best-Fit Cropping · 从文档缓冲区中优先选择能完整塞入剩余空间的最长文档，塞不下时裁切。本文每行构造 T+1 个 token，再错位生成 x/y；没有 padding 不代表没有被裁切内容。">best-fit</abbr> 不等于简单按文件拼接；看清 T+1 到 `[B,T]` 的变化，再在报告手画一个 6-token 的错位例子。

## 失败分流与验收

- `No module named rustbpe/tiktoken/pyarrow/torch`：先核对解释器；若 Conda 环境确实缺依赖，记录 `BLOCKED_DEPENDENCY`，不要把合成流程改成自制假 tokenizer 后冒充通过。
- `pickle` 或词表异常：只使用自己生成或信任来源的 tokenizer；回到隔离目录重新准备，保留原数据。
- `get_token_bytes` 报缺失：今天准备脚本会生成它；已有数据则回溯同一 tokenizer 的生成记录。
- dataloader 长时间没有输出：先查 train split 文件数、row group、text 是否全空；不要无限等待没有数据的 iterator。
- 验收：实际输出 `status=ok`、每个断言可解释；依赖受阻时报告写出缺包名称及未执行范围，明天不可宣称已有合法 checkpoint。
