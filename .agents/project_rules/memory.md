# 跨会话记忆协议

补充 [根 AGENTS.md](../../AGENTS.md)。读索引不需要加载本细则；写入、更新、归档或巡检前完整读取。

## 内容分工

核心规则在根规范，详细知识在 `.agents/docs/`，完整实验和日志保存在原始位置。`.agents/memory/` 保存下次任务需要延续的状态、决策理由、稳定偏好和已验证经验，并指向证据，不维护第二份知识真源。

## 开始任务与续接

1. 读取 `.agents/memory/MEMORY.md`，根据描述展开相关条目。
2. 检查事实的证据和失效条件。记忆是可能过时的背景，不覆盖当前用户指令、项目规范或实际代码。
3. 续接时明确已完成内容、当前阻塞、下一步及结果位置；没有相关记忆时直接工作。不要把计划、推测或尚未执行的检查当成已完成事实。

## 主动写入的触发条件

| 事件 | 保存内容 |
|---|---|
| 用户纠正做法或明确稳定偏好 | 正确做法、理由、适用范围 |
| 影响后续工作的方案确定 | 选择、依据和取舍理由 |
| 环境问题或重复踩坑被验证 | 原因、有效方法、证据位置 |
| 长任务取得阶段成果或遇到阻塞 | 当前状态、结果位置、恢复步骤 |
| 旧记忆被推翻或失效 | 更新事实或归档旧条目，并修复索引 |

遇到以上事件及时判断并维护，不等用户反复说“记住”。结束任务再次检查是否产生值得延续的信息；有则写，无则不写。不要求每轮新增笔记，不保存聊天流水账，不仅为展示“用了记忆”而写入。

## 条目与更新

- 一个文件维护一个可独立召回的主题或任务状态。同主题更新原文件，写实际修改日期，不机械增加一天。
- `user`：用户明确的稳定事实和偏好；`feedback`：方法和纠正；`project`：任务状态、决策、约束；`reference`：资源指针。
- frontmatter 包含 `name`、`description`、`type`、`created`、`updated`。日期为 `YYYY-MM-DD`，name 与文件名匹配，description 用一句话描述何时相关。
- 新增或实质更新的 `feedback` / `project` 正文包含有内容的 `Why:`、`How to apply:`、`Evidence:`、`Invalidates:`。Evidence 是可检查的文件、日志、检查结果或明确用户指令来源；Invalidates 指哪些变化需要重验。稳定偏好可写“用户明确修改偏好时”。
- 活跃任务还应包含已完成、当前阻塞、下一步和结果位置；区分“已验证”“用户决定”“待执行”。完成后去掉无用过程，只保留可复用结论或归档。
- 在索引对应类型下登记一行相对指针。旧条目按相关性逐步补齐新字段，不为迁移批量虚构证据。

例如，一个主题的正文可按下面字段填写真实内容；字段名不是事实，不能留下空值就宣称完成：

```text
事实或决策：
Why:
How to apply:
Evidence:
Invalidates:
```

## 索引、保密与并发

- 软上限 150 行 / 20 KiB，硬上限 200 行 / 25 KiB；行数与 UTF-8 字节数任一超过上限即处理，更新前后均检查。
- 压缩顺序：正文移回详情、合并重复、归档冷数据、重新计数。不能静默丢弃新事实。
- 不记录密钥、Token、密码、私钥、Cookie、恢复码明文或完整个人数据，只保存必要的查找位置。
- 记忆随 `.agents/` 的完整逻辑改动验证后及时提交；不自动推送或复制到其他 Agent 原生记忆目录。版本控制不改变保密要求。
- 仓库无锁，假设单写入者；更新前重读目标文件，避免覆盖别的会话。不要宣称有事务或并发保障。

## 验证

- 索引修改后运行 `python .agents/memory/scripts/memory_check.py .agents/memory/MEMORY.md`。
- 健康巡检运行 `python .agents/memory/scripts/memory_doctor.py .agents/memory`。
- 新式 project / feedback 条目可用 `--require-evidence` 严格检查证据和失效条件；旧条目默认仅给补齐提醒，不因此损坏兼容性。`--no-schema` 仅做结构检查，不能与严格证据检查一起使用。
- 工具不可用时报告，并手动检查格式、指针和大小。脚本只能核对结构，不能证明证据真实、偏好推断正确或模型真正使用了记忆。
- 闭环验收需要任务中实际写入、后续相关任务召回并核验证据、条件变化时更新；不自动开启付费会话或安装 hook 来验证。
