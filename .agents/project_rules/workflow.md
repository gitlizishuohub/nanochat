# 工作与验证流程

补充 [根 AGENTS.md](../../AGENTS.md)。

- 修改前检查 Git 状态和相关调用方，复用已有实现；技术文档中的事实以当前源码核实。
- 跨模块修改核对实际受影响的接口、数据格式和运行契约。
- 临时脚本、中间数据和检查缓存使用操作系统临时目录；正式交付保存在项目对应位置。
- 文档修改检查链接、路径、规则一致性和 diff；代码修改执行已有的相关测试或最小行为验证，避免因小改动启动无关长任务。
- 不编造项目尚不存在的 lint、类型检查或 CI 入口。能力或依赖缺失时明确未验证部分。
- 完成前判断是否出现值得跨会话保存的纠正、决策、已验证问题、阶段成果或阻塞；有则按 [记忆协议](memory.md) 更新，无则不新增。
- 普通任务不重新初始化。根 `AGENTS.md` 与整个 `.agents/`（含 memory）的完整逻辑改动验证后及时提交；其他文件按用户或明确调用的技能授权提交。按精细化提交技能仅暂存当前单一逻辑目的的变更。

## 多智能体协作

- 每次任务开始时，在必要的上下文核对后，评估任务拆分、依赖关系、预期质量、并行收益、协调成本和返工风险，以高效完成完整任务、减少用户等待为目标。主智能体自主决定是否启用子智能体、如何分工及并发数量；本项目明确授权按此判断开展多智能体协作，无需用户每次重复要求。
- 适合独立推进的调查、分模块实现或交叉审查可并行委派；短任务、强依赖步骤或协调成本超过收益的任务由主智能体直接完成。不得为了展示多智能体而增加拆分、重复调查或无效等待。
- 委派时给出明确目标、必要上下文、文件边界和交付要求。子智能体遵守相同项目规范；避免同时修改同一文件，确需共享文件时由主智能体协调写入顺序。工具支持继承时默认继承主智能体的模型和推理强度；用户指定时按可用能力执行。
- 主智能体在子任务运行期间推进不依赖其结果的工作；先处理已就绪的结果，仅在依赖点等待，并根据进展合并、调整或终止重复与失去价值的子任务。结果由主智能体核对、整合和验证，不能仅凭子智能体自述报告通过。
- 在进度中简要说明与任务相关的协作决定和分工，不额外插入审批步骤。多智能体工具不可用时直接采用可行的执行方式；实际影响交付时说明限制。
