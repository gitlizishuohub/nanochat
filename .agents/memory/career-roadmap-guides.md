# W1–W3 教程组织约定

用户决定：将 `.agents/docs/career_roadmap/nanochat_daily_execution_2026-10-01.md` 的 W1–W3 展开为三个周目录内的详细每日指导；每周实验脚本放在该周 `scripts/`。不增加周 README，指导正文在实际操作位置直接用相对链接指向脚本，并说明运行方式、结果解释和验收。

命名约定（2026-10-20 用户授权更新）：W1–W3 每日教程使用全程 `d01_<原主题名>.md` 至 `d21_<原主题名>.md`，保留完整主题名，标题仍用 `Wn Dn`。本次规则替代旧的每周 `D1_`–`D7_` 文件前缀约定。教程配套脚本与新增实验产物均以首次使用或生成日的 `dNN_` 为前缀；跨日复用保留首次编号，公共准备才用 `d00_`。已有实验和外部历史证据不倒改名；nanochat 原生 tokenizer/checkpoint 固定格式保留，并解释真实外部路径。历史验证日期和总计划原文件名保留。

每日正文必须逐项列出使用脚本（用途、阶段、完整输入路径、运行条件）及产物（名称、用途、完整项目相对路径、生成脚本/步骤、自动或条件生成/人工编写/人工导出）。只打印的检查须说明实际保存日志；未满足条件的产物不标为已生成。多行实现、复杂校验和长流程放在独立脚本，正文保留短调用、参数解释、产物和验收。继续保持周 scripts 目录和正文直链，不增加周 README。

流程伴读（2026-10-21 用户要求）：用户希望随着 D1–D21 逐步阅读 LLM 流程。21 篇每日教程均在首个操作章节之前提供“当天的流程阅读”，直接链接指定小节，列出重点、可跳过内容和当天口述自检；总映射仅维护在流程栏目 README。每天建议 10–20 分钟，不增加手写报告或实验任务，深入算法留待 D21 后按方向补读。

环境选择：用户在同一任务中明确要求先创建 Conda 环境，并命名为 `nanochat`。后续教程以 `conda activate nanochat` 后运行 `python` 为主；不要默认切回项目 `.venv` 或使用会另建 `.venv` 的 `uv run`。

终端与日志（2026-10-22 用户纠正及验证）：用户终端已自动激活 nanochat，每日教程不再重复 source conda.sh 或 conda activate，仍检查 sys.executable。D01–D21 原有全局 exec 重定向会把 VS Code OSC 633、提示符及粘贴模式控制字符写入日志；现改为各 Bash 花括号命令组局部重定向到 tee，变量留在当前 shell，返回最后命令状态。单条退出码仍需即时记录；显式文件重定向保留各自目标。旧终端须关闭后新开，文档修改不会停止已有重定向。

每日验证交流（2026-10-20 用户纠正）：用户不喜欢手写 report，要求直接修改每日教程，明确每天特异性的验证问题，由用户自行验证后与助手交流。每日正文应提供当天专属的问题和所需证据，允许在聊天中逐项简答；人工 Markdown 报告为可选整理，不作为每日验收前置。保留自动日志、结构化结果、真实命令与退出码以及未验证边界；简历、复现入口等实际材料与日常报告区分，允许先交流核对再整理。不能只套用一份通用五项报告模板。
